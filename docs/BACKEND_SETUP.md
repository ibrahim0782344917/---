# إعداد قاعدة بيانات شتريد المستقلة

**لا تطبق هذا الملف على مشاريع siraj أو siraj123 أو NovaCircle.**

## التأسيس
1. أنشئ مشروع Supabase جديد باسم `shitreed` داخل **المؤسسة التي يحددها صاحب المشروع صراحة**. الإنشاء قد يتطلب رسوماً ويجب موافقة المستخدم على أي تكلفة.
2. طبّق بالترتيب ملف `supabase/migrations/20261107090000_marketplace_foundation.sql` عبر Migrations.
3. راجع في لوحة Auth أن Email/Password مفعّل، وأكمل تفعيل بريد تأكيد المستخدمين وإعداد مزود البريد الإنتاجي قبل الإطلاق.
4. احصل فقط على **Project URL** و **Publishable Key**. لا تضع `service_role` أو `secret` في تطبيق الهاتف ولا بالمستودع.
5. عند البناء مرر القيم بمتغيرات إعداد البناء:
   ```bash
   flutter build apk --debug \
     --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
     --dart-define=SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_PUBLIC_KEY
   ```
6. يجب اختبار التسجيل ثم تسجيل الدخول، والتأكد من إنشاء صف في `customer_profiles`.
7. اختبر العزل بين حسابين: لا يجوز لزبون قراءة ملف مستخدم آخر، ولا تعديل حالة اعتماد متجر، ولا تعديل منتجات متجر آخر.

## حالة المزايا الآن
- **التسجيل الفعلي:** تمت برمجة الواجهات والنداءات، لكنه لا يعمل من دون قاعدة مستقلة ومفاتيحها العلنية.
- **تصفح المحلات الحقيقية:** يتم جلب المتاجر ذات `status = approved` فقط عبر RLS؛ القائمة ستكون فارغة قبل إضافة المتاجر واعتمادها.
- **Google Places:** غير مفعّل. تحتاج مفتاح API مقيد، سياسة خصوصية، عرض الإسناد، واحترام شروط التخزين والاستخدام. لا نفترض توفر أسعار المنتجات من Google.
- **الدفع والطلبات:** غير مفعّلة. لا تعرّض جدول طلبات للكتابة من الجوال قبل بناء معاملة خادمية تتحقق من الأسعار والمخزون وصاحب المتجر.
- **الموقع التلقائي:** يحتاج إذن المستخدم ومزود خرائط، غير مفعّل حالياً.

## اعتماد متجر جديد
`stores.status` يبدأ `pending`. لا يستطيع صاحب المتجر تعديل الحالة؛ إدارة المشروع هي التي تعتمد المتجر بعد التحقق (حالياً من Supabase Dashboard). المنتج لا يظهر للزوار إلا عندما يكون `is_active = true` والمتجر معتمداً.

## الخطوات التالية
- إنشاء المشروع المنفصل بعد تحديد المؤسسة والتكلفة.
- تطبيق وترصيد/تدقيق migration.
- تخصيص بناء Android بوصل Supabase Publishable Key وProject URL.
- اختبارات فعلية بحسابين وبيانات متاجر مصرح بها.
- تجهيز لوحة صاحب المتجر ثم الطلبات والمندوب والإدارة.
