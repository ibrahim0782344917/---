# شتريد — المحفظة والدردشة والرقابة الإدارية

**التاريخ:** 22 نوفمبر 2026
**الفرع:** feature/wallet-chat-admin-safe
**الحالة:** كود للمراجعة؛ لم يطبق على قاعدة الإنتاج ولم يتم تشغيله على هاتف حقيقي.

## محتوى فرع التطوير
- دفتر قيود مالي خاص داخل مخطط shitreed_finance منفصل عن API العام؛ كل حركة بمجموع صفر وقيدين على الأقل. التصحيح يتم بقيود تعويضية.
- محفظة زبون وتاجر بالدينار العراقي، ونقاط مكافآت مستقلة بعملة افتراضية POINT.
- وظائف قراءة الرصيد والحركة فقط. الشحن والسحب والتحويل غير متاحين في التطبيق.
- محادثات خاصة بين الزبون والمتجر المعتمد؛ لا يطّلع عليها إلا الطرفان المخوّلان. صلاحيات RLS والتأكد من ملكية المحل وقت الإرسال.
- دعم اشتراك Supabase Realtime للرسائل مع حدود إرسال على الخادم.
- تطبيق الزبون: محفظة ونقاط، صندوق الرسائل، مراسلة المتجر من صفحته.
- تطبيق التاجر: صندوق محادثات، صفحة رصيد، صفحة ملخص إداري لا تعرض نصوص الدردشة ولا أرقام هواتف الزبائن.

## خطوات الاختبار قبل الإطلاق
1. تأكد من وجود نسخة احتياطية قابلة للاستعادة ومن عدم تعارض الهجرة مع قاعدة شتريد الحالية.
2. أنشئ Staging منفصلاً بعد موافقة أي رسوم؛ لم ننشئه في هذا العمل لأنه يطلب تأكيد تكلفة.
3. نفّذ هجرة SQL في Staging وافحص سياسات RLS وأذونات الجداول والوظائف وصحة نشر Realtime.
4. اختبر حساب زبون A وتاجر B يملك متجراً معتمداً وزبون C غريباً ومشرف D. تأكد أن C لا يقرأ رسائل A/B، وأن B لا يقرأ محادثات متجر آخر، وأن الإدارة لا تقرأ مضمون الدردشة.
5. اختبر نقل ملكية متجر: القديم يُحجب عن المالك الجديد، والإرسال يتوقف تلقائياً عند تغير المالك حتى مراجعة الدعم.
6. اختبر قيود دفتر المالية: قيدان متوازنان ينجحان، غير المتوازن يفشل عند COMMIT، اختلاف العملة يفشل، والحذف والتعديل يفشلان.
7. تأكد أن مستخدمي anon وauthenticated لا يستطيعون الكتابة في الدفتر المالي أو رؤية مخطط shitreed_finance مباشرة.
8. شغّل مستشار Supabase الأمني، وحلل Flutter وأجرِ اختبارات وحدة وبناء APK واختبار هاتفين منفصلين.

## الأمان والإطلاق
- لا تضف أرصدة بسبب طلبات الدفع عند الاستلام إلا بعد إثبات التحصيل والتسوية.
- الشحن، الاسترجاع، التحويل والسحب الحقيقي تتطلب مزود دفع مرخصاً وإثبات مطابقة Webhooks وتكرار آمن وسجل تدقيق.
- لا تضع مفاتيح service_role في Flutter أو ملفات GitHub.
- نقاط المكافآت ليست أموالاً ولا تستبدل نقداً.
- أي أداة إدارية لتغيير الأرصدة تحتاج موافقات متعددة وصلاحيات محدودة ومراجعة مستقلة.
- لا توجد هنا مرفقات محادثة ولا مكالمات ولا إشعارات FCM ولا أدوات نزاعات مالية كاملة.
- لا تدمج مع main ولا تنشر للإنتاج قبل نجاح اختبارات Staging والأمان وموافقة صاحب المشروع.
