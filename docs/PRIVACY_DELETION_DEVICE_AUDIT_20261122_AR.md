# شتريد — فحص حماية البيانات وحذف الحساب وتجربة الأجهزة

**التاريخ:** 22 نوفمبر 2026
**النطاق:** GitHub PR #18، فرع feature/wallet-chat-admin-safe
**البيئة:** اختبارات معزولة في GitHub Actions؛ لا تعديل على قاعدة الإنتاج أو بيانات الزبائن.

## عناصر اختُبرت

1. الوصول إلى محادثات الزبون والتاجر: اختبارات RLS بين زبون، صاحب متجر، مستخدم غير مشارك، وحساب إدارة. لا يسمح للمستخدم الغريب بقراءة الرسائل أو إرسالها.
2. المحفظة: عزل رصيد الزبون عن غيره، منع وصول مستخدم عادي إلى الدفتر المالي، رفض قيود غير متوازنة وقت COMMIT. نقاط المكافآت منفصلة عن IQD.
3. طلب حذف الحساب: أضيفت للزبون شاشة موافقة صريحة ومتابعة حالة الطلب؛ لا يوجد حذف تلقائي. أضيفت وظيفة خادمية idempotent، وتصححت أذونات قراءة الطلبات الشخصية.
4. اختبارات قاعدة بيانات معزولة تتحقق من انفراد كل مستخدم بطلبات حذفه، منع التلاعب باسم مستخدم آخر، عدم إنشاء طلب مكرر، وأن مستخدمي Auth لم يتم حذفهم بمجرد الطلب. توجد اختبارات إضافية لطلبات التاجر.
5. اختبارات Flutter واجهات بأحجام 320 و360 و393 و600 و800 بكسل، واختبار واجهة تسجيل التاجر بعروض مختلفة، إضافة إلى اختبار الإقلاع على محاكي Android 14، دون أسرار أو ربط إنتاج. ارجع إلى سجل CI للنتائج النهائية لكل تشغيل.

## نتائج فحص الأمن بالقراءة فقط (Supabase production)
- customer_deletion_requests: توجد سياسات RLS لقراءة طلب المستخدم، لكن لم تكن هناك صلاحية SELECT ممنوحة لـ authenticated. أضفنا إصلاحاً في فرع التطوير، لم يُطبَّق على الإنتاج.
- stores.phone: تم التحقق أن anon وauthenticated يملكان SELECT على عمود الهاتف، وأن هناك سياسة تتيح القراءة العامة لصفوف المتاجر المعتمدة. إخفاء الرقم من Flutter لا يكفي لمنع طلبه عبر API. **مانع خصوصية محتمل، موثَّق في Issue #19.** لا تُلغَ الصلاحيات دون ترحيل وبناء مسار التاجر والتطبيق العام واختبارات الانحدار.
- Supabase Security Advisor: تحذير حماية كلمات المرور المسربة غير مفعّلة، وتحذيرات متعددة على دوال SECURITY DEFINER المسموح لعميل مصدّق باستدعائها. ليست دليلاً بحد ذاتها على تسريب، لكن يلزم تدقيق منطق المصادقة والحدود.
- لا تؤكد نتائج CI المعزولة فحص حماية كل جدول/ملف أو تعارض جلسات JWT قيد الاستخدام على الإنتاج.

## حذف الحساب: ما زال غير مكتمل
- المسار الحالي **إنشاء طلب حذف ومتابعة الحالة**؛ لا يحذف auth.users أو بيانات الطلبات أو المحادثات أو الصور تلقائياً.
- تنفيذ الحذف النهائي يحتاج خدمة إدارية موثوقة: إثبات الملكية، التحقق من الطلبات المفتوحة والرصيد والنزاعات، اتخاذ قرار سياسة الاحتفاظ، تسوية/إزالة المراجع، حذف ملفات التخزين المخصصة، إزالة صلاحيات وتوكنات الجلسات، تنفيذ Auth Admin API من الخادم، وتوثيق النتيجة.
- بعض المفاتيح الأجنبية على المتاجر والسجلات المالية والمراسلات تمنع حذف auth.users المباشر. يجب عدم تجاوزها بحذف جماعي أو CASCADE عشوائي.
- Google Play يتطلب مسار حذف عملياً خارج التطبيق عبر رابط ويب عام، وليس مجرد ملف HTML مسودة. يجب ربط مسار طلب الحذف والتحقق منه قبل النشر.
- حماية كلمات المرور المسرّبة والتشديد الأمني لصلاحيات الإدارة يجب أن يكملا قبل إنتاج.

## أجهزة Android
- اجتياز اختبارات حجم الشاشة هو محاكاة Flutter لا تعادل تجربة هاتف حقيقي.
- محاكي Android 14 في CI يشغّل APK زبون/تاجر بدون مفاتيح إنتاج ويحفظ صور الشاشة كأثر CI عند نجاحه.
- **لم يُختبر بعد على هاتف Android فعلي** تسجيل دخول حقيقي، حذف الحساب من حسابين، ضعف الشبكة، الاستئناف من الخلفية، إشعارات FCM، خرائط بمفتاح مقيد أو مراسلات المتجر.

## القرار
لا تدمج هذا الفرع إلى main ولا تنشره قبل إصلاح Issue #19 حسب سياسة الخصوصية، وتمكين مسار حذف حقيقي خارج التطبيق، وإكمال الاختبار على حسابات Staging وأجهزة فعلية، ومراجعة نتائج CI النهائية.
