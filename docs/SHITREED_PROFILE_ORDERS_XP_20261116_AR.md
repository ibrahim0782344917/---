# شتريد: تطوير البروفايلات والطلبات والمستويات — 16 نوفمبر 2026

## ما أُنجز فعلياً

### قاعدة Supabase (مشروع شتريد)
- إضافة `shitreed_profiles`: اسم ومدينة ونبذة وصورة؛ صاحب الحساب فقط يعدّل.
- إضافة `shitreed_saved_addresses`: عناوين توصيل متعددة خاصة بالحساب.
- إضافة Storage bucket `shitreed-avatars`: صور عامة بحد أقصى 2MB، ومجلد خاص لكل مستخدم للصورة.
- إضافة `shitreed_xp_rules`, `shitreed_xp_events`, `shitreed_level_thresholds`: 100 مستوى افتراضي.
- إضافة `shitreed_user_badges` و`shitreed_profile_admin_audit`: شارات وصلاحيات مراجعة مؤرخة.
- نقاط إكمال الملف: 20 XP مرة واحدة فقط عند اكتمال الاسم والمدينة والنبذة.
- قواعد شراء/تقييم/بيع/مشاركة/نشاط موجودة **معطّلة** حتى تتوفر أحداث مكتملة موثقة وحماية ضد الاحتيال.
- دالة `shitreed_my_xp_total()` تعتمد على مجموع نقاط المستخدم في قاعدة البيانات لا على آخر النتائج المعروضة.
- دوال Admin: `shitreed_admin_set_badge`, `shitreed_admin_set_level_threshold`,
  `shitreed_admin_set_xp_rule` تشترط Super Admin + MFA (AAL2)، وتسجل تغييراتها.

### تطبيق الزبون
- صفحة حسابي صارت بروفايل مع صورة من المعرض، اسم، مدينة، نبذة، شارات، XP وشريط تقدم المستوى.
- حفظ عناوين توصيل متعددة واختيار عنوان محفوظ عند الشراء.
- سجل طلبات حقيقي قابل للتصفية حسب الحالة، وإلغاء الطلب الجديد بتأكيد صريح.
- خط الطلبات والتفاصيل بقي مربوطاً بخدمة Supabase الفعلية.

### تطبيق التاجر
- صفحة بروفايل التاجر وإدارة الألقاب والمستوى نفسه.
- قائمة الطلبات بفلاتر حالة الطلب (جديد، مقبول، تحضير، جاهز، مرفوض، ملغي).
- منع محاولة التاجر قبول طلب أُنشئ من حسابه الشخصي؛ يمكنه إلغاء طلبه التجريبي بتأكيد.
- عرض الأخطاء المعرّفة بشكل آمن دون تسريب رسائل SQL.

### تطبيق Admin
- شاشة جديدة للتحكم بالرتب/الألقاب والتوثيق الأزرق، تغيير حدود XP للمستويات وقواعد المكافآت.
- البحث عن المستخدم عبر البريد موجود مع صلاحية Super Admin.
- كل تغييرات الامتياز تحتاج MFA AAL2.

## اختبارات الجودة اللازمة
- بناء جديد متكامل لتطبيقات Android الثلاثة عبر GitHub Actions.
- E2E بحساب زبون وآخر تاجر مختلفين، وبدون إنشاء أو إلغاء طلبات إنتاج فعلية بغير تصريح.
- تسجيل دخول مدير مع MFA واختبار منح الشارة وسحبها.
- اختبار أول حفظ بروفايل يمنح 20 XP **مرة واحدة** فقط؛ تحديث البروفايل لا يكرر المكافأة.
- اختبار رفع الصور مع مستخدمين منفصلين وعدم الوصول إلى سجلات وعناوين الآخر.
- اختبار حالات رفض الطلب والإرجاع والمطالبة والتوصيل الفعلي قبل إصدار التجارة الكامل.

## نواقص معروفة وليست جاهزة بعد
- XP البيع والشراء يحتاج إثبات تسليم وتحويل مالي وتسوية وسياسة رد/عكس النقاط.
- مستويات 100+ قابلة للتوسعة، لكن جدول التحكم الحالي يبدأ بـ100 مستوى.
- توثيق الهوية/التاجر يتطلب سير مراجعة مستندات معتمدة قبل منح العلامة.
- إدارة الشحن والمندوبين والإرجاعات، والمدفوعات الإلكترونية، وGoogle Places الحي تحتاج اختبارات وربطاً منفصلاً.
- هذه تغييرات تطوير على الفروع، وليست تحديثاً تلقائياً لملفات APK الموجودة على الهاتف، وليست إعلاناً بالنشر التجاري الكامل.
