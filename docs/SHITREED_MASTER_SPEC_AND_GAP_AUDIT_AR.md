# شتريد؟ موجود! — المواصفات النهائية المتتبعة وفجوات التنفيذ

> مراجعة 14 نوفمبر 2026. المصدر: طلبات المالك في المحادثة + المستودع الحالي + فحص قاعدة Supabase + GitHub Actions. هذه خطة تعاقدية هندسية، وعلامة [x] أدناه تعني "المتطلب معتمد" فقط؛ لا تعني أنه منفّذ.

## الهدف التجاري الفارق

الزبون يكتشف **محلات موجودة على الأرض** من خلال Google Maps/Places ويشاهد حالتها العامة. وجود محل على Google لا يعني اشتراكه في شتريد، أو توثيقه، أو إتاحة شراء منتجاته. بعد طلب الملكية والتحقق من صاحب المحل والموافقة الإدارية، يضيف التاجر **كتالوجاً مستقلاً خاصاً به** وأسعاره ومخزونه. شتريد تاجر يدير هذا الكتالوج والطلبات؛ Admin يراقب الملكية والتوثيق والمحتوى والعمليات.

## منظومة الحسابات والتطبيقات

### الزبون (Android + واجهة ويب)
- [x] حساب حقيقي، دخول آمن، جلسات وأجهزة، بروفايل وعناوين متعددة، حذف حساب فعلي.

- [x] شاشة محل غير مسجل = معلومات مكان فقط؛ شاشة محل معتمد = منتجات منشورة من شتريد، لا بيانات مفترضة من Google.
- [x] صفحة المنتج بصور/فيديو/متغيرات/مخزون/تقييمات، ومقارنة وعناصر مفضلة.
- [x] سلة متعددة التجار (تقسيم طلب ومصاريف ومرتجعات لكل متجر)، كوبونات، العنوان، الاستلام أو التوصيل، سعر نهائي.
- [x] حالات الطلب والإلغاء والاسترداد والنزاع وإثبات التسليم.
- [x] رسائل مباشرة مع التاجر والدعم والتبليغ والحظر والصور، إشعارات وتوافق الشبكات الضعيفة.
- [x] XP/ألقاب/رتب/شارة زرقاء منفصلة عن الصلاحيات والمحفظة النقدية.
- [x] العربية/الكردية/الإنجليزية، RTL/LTR، الوضع الداكن، الوصول، الأجهزة اللوحية.

### التاجر (Android + واجهة ويب)

- [x] فروع متعددة وموظفون مع أقل صلاحية ممكنة وأوقات عمل ومواقع ومخزون لكل فرع.
- [x] كتالوج يدوي/CSV/باركود/متغيرات/صور؛ منع منتجات مخالفة أو مسروقة المحتوى.
- [x] قبول/رفض/تحضير/تسليم الطلب وفواتير، مناطق توصيل، ومندوبو توصيل عند الاعتماد.
- [x] رسوم وعمولات وتقارير صافي ومستحقات وتسويات وسحوبات مرخصة.
- [x] عروض وكوبونات وإعلانات اختيارية بعد مراجعة الإدارة ووضوح الرسوم.
- [x] دردشة العملاء والدعم والبلاغات والردود الجاهزة وإحصاءات تجارية حقيقية.

## سياسة العمولة المعتمدة تجارياً (ليست منفذة فعلياً بعد)
- 1% من **صافي قيمة المنتجات المباعة بعد خصومات المنتج** كافتراضي، ولا تضاف رسوم التوصيل أو الضرائب إلى الأساس إلا بسياسة جديدة معلنة.
- تقف النسبة العامة عند 100 نقطة أساس (basis points). استثناءات لفئة أو تاجر أو إعفاء مؤقت وفق قواعد أسبقية: إعفاء التاجر > نسبة التاجر > نسبة الفئة > النسبة العامة؛ تعدد الفئات يُحتسب لكل سطر طلب.
- تحفظ قاعدة ونسبة العمولة عند إنشاء الطلب في بيانات لا يعدّلها التاجر. لا ينشأ **استحقاق عمولة** إلا عند اكتمال التسليم/البيع والتحصيل وفق دليل مستقل.
- الإلغاء/عدم التسليم = صفر مستحق؛ الاسترجاع الجزئي يعكس العمولة النسبية بسجل عكسي، لا تعدّل معاملة قديمة.
- تسوية COD تتطلب آلية قبض رسوم فعلية، لا تكفي خانة محاسبية. تظل الرسوم "مستحقة" لا "محصّلة" حتى يوجد دليل دفع.
- تشمل لوحة Admin سجل كافة التعديلات، وأشعاراً للتاجر قبل التغيير، وتفعيلها للطلبات الجديدة فقط.
- أمثلة: قيمة منتجات 10,000 -> 100 د.ع؛ 50,000 -> 500 د.ع؛ 100,000 -> 1,000 د.ع؛ 1,000,000 -> 10,000 د.ع (قبل رسوم أخرى).

## XP والرتب
- الألقاب تعبير بصري ولا ترفع RBAC. إظهار نوع الحساب الحقيقي (زبون، تاجر، Admin) يتم من الخادم.
- XP مقترحة: بروفايل مكتمل 20، طلب مكتمل ومحصّل 30، تقييم شراء موثّق 10، مشاركة حقيقية 5، بيع مكتمل 40، نشاط مؤهل يومي 5. جميعها قابلة للتعديل بإدارة مخولة وتحتاج حدود وتحققاً ومنع تكرار.
- مستويات مرجعية: 1–10 مبتدئ، 11–25 نشيط، 26–50 مميز، 51–75 محترف، 76–99 أسطوري، 100+ نخبة. عتبات XP تحفظ مركزياً وبنسخ مؤرخة حتى لا تتغير النتائج تاريخياً دون سجل.
- حالة عرض مثال فقط: "المستوى 25 — 2,450 / 3,000 XP"، لا بيانات مستخدم حقيقية.
- شارة زرقاء بعد تحقق محدد النطاق، سبب وتاريخ انتهاء وسجل قرار؛ توثيق الهوية/الملكية لا يمثل ضمان جودة أو سلامة المنتج.

## مواصفات قانونية وتشغيلية مُضافة بعد المراجعة
1. **تمييز المحتوى:** `google_place_id` يمكن حفظه؛ باقي معلومات Google تُجلب وتُعرض ضمن شروط Places API مع العلامة والاعتمادات وسياسة تخزين وعدم scraping. بيانات التاجر الأصلية تُحفظ بمصدرها المستقل.
2. **المطالبة بالمحل:** سجل مطالبات ملكية متعدد الأدلة، موافقات/رفض/استئناف، حماية المستندات في تخزين خاص، منع المطالبة التلقائية بمجرد العثور على Google ID.
3. **قواعد الفرع:** مكان حقيقي لكل فرع، أسعار ومخزون، موظفون وساعات وعطلات ومنطقة توصيل ورسوم وحظر المنتجات محلياً.
4. **دورة الطلب:** حالات انتقال صريحة ومصدر الحقيقة واحد مع تسجيل وقت القبول والإسناد والاستلام والتسليم، فشل التسليم، إثبات التسليم، تعويضات، وتأمين ضد تكرار الدفع والطلبات.
5. **المدفوعات:** ZainCash/SuperQi/Mastercard تحتاج عقد مزود وتجربة Sandbox وتوقيع webhook ومصالحة؛ محفظة النقد منفصلة قانونياً عن النقاط والمكافآت غير النقدية؛ IQD أساسي وUSD عرض فقط بسعر موثق.
6. **سجلات مالية:** دفتر مزدوج غير قابل لإعادة كتابة التاريخ، خصم وعكس ومصالحة وتصدير واسترجاعات ومحافظة على مبالغ العملات كأعداد صحيحة.
7. **الثقة:** تقييمات شراء موثقة مع آلية تبليغ ومنع تضارب المصالح، سياسات الإعلانات، كشف الرسائل المسيئة والمحتوى المحظور.
8. **الخصوصية:** موافقات المستخدم والاحتفاظ والحذف الحقيقي، سياسة الخصوصية والكشف عن الموقع والإشعارات، مع إجراءات تنزيل/تصحيح بيانات الحسابات.
9. **الأمن:** اختبارات وصول زبون↔زبون، تاجر↔تاجر، Admin↔غير Admin، RLS، MFA، إدارة أسرار، سجلات، نسخ احتياطية واستعادة.
10. **التصميم:** شتريد زبون أخضر زمردي، تاجر أخضر مع ذهبي، Admin كحلي/أزرق، هوية RTL موحدة مع إشارات تحميل وخطأ وإفراغ وغياب الإنترنت.
11. **متجر Play:** AAB موقّع، API 36، بيانات الأمان، حذف الحساب داخل التطبيق وخارجه **وتنفيذه الفعلي**، سياسة الخصوصية والشروط، اختبار أجهزة، روابط الدعم، عدم إعلان ميزة دفع غير مفعلة.
12. **التجارة والتشغيل:** الجهة القانونية، الترخيص التجاري، الاتفاقية، الفواتير والضرائب المحلية، تعاقدات المندوبين، مدة إرجاع موثقة، قناة دعم رسمية، خطة للتعامل مع النزاعات.
13. **الإيرادات الاختيارية:** اشتراكات التجار والإعلانات المميزة ليست مفعلة؛ لا تُنشر رسومها قبل عقود وسياسة مراجعة ومقاييس حقيقية.
14. **إدارة الموقع:** لا تعرض صفحة تعريفية للتاجر أو Admin على أنها بوابة تحكم فعلية. يجب توفير دخول حقيقي وصلاحيات وتدفقات منفصلة قبل الإعلان.
15. **التوافر:** فصل Production عن Staging حتى على Railway، وإصدار تدريجي حسب بغداد ثم المحافظات، ومراقبة الميزانية/Google Places والقياس وتحليل الأعطال.

## ترتيب قبول الإصدار
1. سلامة المتاجر والمطالبة وإثبات الملكية والخريطة، مع ربط فعلي وآمن لـPlaces.
2. اختبار تسجيل الدخول والتاجر ودورة COD كاملة، وإثبات التسليم، وحماية RLS/المعالجة عند الإلغاء.
3. العمولة والمال ودفتر القيود والمصالحة ورسوم التوصيل.
4. واجهات Admin والتاجر، والدردشة، وإدارة التوثيق والرتب.
5. الحذف الفعلي، الدعم، شروط البيع والخصوصية الموقعة، اختبارات أجهزة وإطلاق AAB.
6. إعلان النشر العام بعد كل بوابات القبول، ثم الإعلانات والاشتراكات والمدفوعات المرخصة مرحلياً.

**قاعدة التنفيذ:** تُنشأ تغييرات التطوير على فرع مع CI ومراجعة. لا تُستبدل البنية الرئيسية أو تُضاف بوابة دفع مدفوعة أو تُحذف بيانات دون اختبار وموافقة تشغيلية مناسبة.
