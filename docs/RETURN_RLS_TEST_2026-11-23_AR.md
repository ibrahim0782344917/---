# اختبار صلاحيات استلام الطلبات والاسترجاع — 23 نوفمبر 2026

**البيئة:** Supabase `shitreed-test` فقط. **النشر والإنتاج متوقفان.**

## اختبارات ناجحة عبر PostgreSQL داخل BEGIN / ROLLBACK
- التاجر لا يمكنه استدعاء `confirm_cash_order_receipt` لتأكيد استلام طلب المشتري
- المشتري يستطيع تأكيد استلام طلبه عندما تكون حالته `ready`
- المشتري يستطيع فتح `return_requests` بعد تأكيد التسليم
- المشتري لا يستطيع تحويل طلب الاسترجاع بنفسه إلى `approved`
- التاجر لا يستطيع تقديم طلب استرجاع باسم المشتري
- التاجر لا يستطيع اعتماد طلب الاسترجاع
- حساب مدير الاختبار يستطيع تغيير حالة الطلب إلى `under_review` ثم `approved` باستخدام `review_return_request`
- بعد `ROLLBACK`: بقيت 5 طلبات أصلية، و0 طلبات استرجاع. لم تجر أي حركة مالية أو رد أموال.

**قيود لم تُختبر بعد:** التطبيق على هاتفين حقيقيين، التكامل عبر JWT حقيقي/واجهة PostgREST، مهلة 14 يومًا عند حدودها، رفع إثبات التلف، تدخل المندوب، حل النزاعات، وسياسة التعويض والتحويل المالي. اعتماد طلب الاسترجاع لا يعني صرف تعويض.

**الخطوة التالية:** إجراء اختبارات HTTP بتوكنات اختبار حقيقية وتحديد سياسة الاسترجاع القابلة للتعديل من لوحة الإدارة.

**أمن البيانات:** بيانات الزبائن السابقة تبقى في جدول مستقل ومحمي؛ استيراد 4,952 سجلًا ما زال معلّقًا حتى الوصول إلى ملف SQL على الجهاز.
