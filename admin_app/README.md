# شتريد — تطبيق الإدارة المستقل (Flutter / Android)

لوحة تحكم عربية RTL تعمل على الهاتف، داخل **المستودع نفسه** الذي يحتوي على تطبيق الزبون وتطبيق التاجر. هي لا تستبدلهما ولا تغير تصميمهما. البناء ينتج **Debug APK للاختبار** بحزمة `com.shitreed.shitreed_admin`.

## أقسام النظام المنفذة

- لوحة قيادة تعرض أعداد المتاجر والطلبات والمنتجات والزبائن وقيمة الطلبات غير الملغاة؛ القيمة **ليست إيراداً نقدياً محصلاً**.
- مراجعة المتاجر: اعتماد طلب موثق، إيقاف متجر معتمد، إعادة متجر موقوف للمراجعة.
- إدارة المنتجات: إخفاء منتج أو إعادته للنشر فقط عندما يكون المتجر معتمداً.
- إدارة الطلبات: قبول ورفض وتحضير وجاهز وإلغاء حسب حالات الطلب؛ إلغاء أو رفض طلب يعيد المخزون **مرة واحدة** داخل معاملة قاعدة البيانات.
- قائمة الحسابات: استعراض ملفات الزبائن، بدون عرض كلمات مرور أو تعديل الحسابات بشكل غير مدعوم.
- فريق الإدارة: إضافة موظفين من مستخدمين مسجلين موجودين، وتحديد أدوار جزئية أو إيقاف الدور (للمدير العام فقط).
- سجل تغيير إداري يضم الفاعل والحالة السابقة والجديدة والسبب والوقت.
- صفحة دخول محمية بجلسة Supabase Auth، وصلاحيات `app_metadata` الموثوقة أو أدوار الفريق المسجلة على الخادم.
- تصفح دفعات من 30 سجلاً؛ لا يسمح عميل الهاتف بإرسال أوامر SQL خام.

## الأدوار والصلاحيات

| الدور | الصلاحيات |
| --- | --- |
| `super_admin` | جميع الأقسام، منح أدوار موظفين |
| `operations` | المتاجر والمنتجات والطلبات والزبائن والسجل |
| `merchant_reviewer` | اعتماد أو إيقاف المتاجر |
| `catalog_manager` | إظهار أو إخفاء المنتجات |
| `support` | الطلبات والزبائن |
| `viewer` | الاطلاع على اللوحة والمتاجر والمنتجات |

**الصلاحية تُفحص داخل كل RPC في PostgreSQL ولا تعتمد على إخفاء زر في Flutter.**
لا توجد مفاتيح `service_role` في APK، ولا يمكن تسجيل مدير عام من واجهة التطبيق.

## خطوات التفعيل الآمن

1. راجع الترحيل `supabase/migrations/20261114120000_admin_console.sql` واختبره على قاعدة Staging أو قاعدة اختبار **قبل** تطبيقه على مشروع `ltwncrewggdrjevakwpb`. هذا الفرع لا ينفذ الترحيل على Production.
2. في لوحة Supabase Auth، عيّن أول مدير عام بطريقة موثوقة فقط عبر `auth.users.raw_app_meta_data` بحيث `shitreed_role = admin`. لا تضع هذا في `user_metadata` القابلة للتعديل من الهاتف. لا تنشئ هذا الحساب تلقائياً.
3. بعد الترحيل، سجل دخول المدير العام بنفس البريد وكلمة المرور المستخدمة في Auth. يمكنه منح الأدوار لغيره باستخدام UUID الحساب المسجل وسبب موثّق.
4. حمّل `Shitreed-Admin-Debug-APK` من GitHub Actions بعد نجاح فحوص `flutter analyze` و `flutter test`. هذا ليس إصداراً موقعاً لنشر Google Play.

## حدود التنفيذ الحالية

- التحكم في متاجر شتريد المسجلة في Supabase فقط، **وليس** تعديل قوائم Google Places التابعة لأصحاب أعمال آخرين.
- لا يوجد حالياً نظام مدفوعات إلكترونية أو مندوبين أو محادثات أو تحصيل مالي جاهز للربط؛ لا نعرض أزراراً توهم بتفعيلها.
- لا توجد وظيفة حظر مستخدم شامل، أو حذف حساب، أو تغيير ملكية متجر، أو تعديل مالي مباشر: تتطلب إجراءات مستقلة وحماية في جميع مسارات API.
- فحص RLS وتكامل المخزون والتزامن بحسابات مختلفة مطلوب قبل تشغيل عمليات الإدارة على بيانات حقيقية.
- كل قرارات الاعتماد يجب أن تسبقها مراجعة ملكية المتجر ومعلوماته، حتى لو اجتاز الإدخال التحقق الآلي.
- لا يتم تفعيل Google Places أو الدفع أو خدمة مدفوعة أو ترحيل قاعدة الإنتاج عند فتح Pull Request.


## إصدار Admin Pro 0.2 — وظائف متصلة بخادم شتريد

يستند تطوير الواجهة إلى أنماط Shopify Admin وSquare Dashboard:
فصل التشغيل عن صلاحيات الفريق، عرض بيانات حقيقية، واتباع سجل تدقيق للعمليات.

- **بحث وفلاتر وترقيم صفحات من الخادم**: متاجر ومنتجات وطلبات وزبائن وموظفون وسجل العمليات؛ يمنع تجاوز الصلاحيات في PostgreSQL. الحد 25 صفاً لكل صفحة والحد الأقصى 80 محرفاً للبحث.
- **مؤشر أسبوعي حقيقي**: عدد الطلبات في آخر سبعة أيام مصدره جداول شتريد، بدون بيانات اصطناعية. قيمة الطلبات لا تمثل إيراداً محصلاً.
- **تفاصيل الطلب**: بنود الطلب وكمياتها وملاحظاته وتاريخ تغيّر الحالات، فقط للأدوار المخولة.
- **إدارة المخزون والأسعار**: ضبط مخزون المنتج بأمر نسبي أو تعديل سعره؛ التحقق من الحدود، قفل السجل، وكتابة السبب والفاعل والقيمة السابقة والجديدة إلى سجل الإدارة. لا توجد أوامر حذف مباشر.
- **مراجعة المتاجر**: اعتماد، رفض من حالة الانتظار، إيقاف، وإرجاع للمراجعة، مع سجل تدقيق مزدوج.
- **إضافة موظف بالبريد**: استعلام تطابق تام للبريد عن مستخدم موجود في Supabase Auth، متاح للمدير العام فقط، ثم اختيار دوره. لا ينشئ مستخدماً تلقائياً.
- **اختبار حدود الصلاحيات**: منع قراءة الطلبات والمستخدمين أو تعديل المخزون والسعر من حساب غير إداري. اختبارات عدم الوجود لا تعدل بيانات الإنتاج.
