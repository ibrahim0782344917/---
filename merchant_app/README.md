# شتريد تاجر | Shitreed Merchant

تطبيق Android Flutter مستقل بأيقونة واسم «شتريد تاجر» لأصحاب المتاجر، **لا يستبدل تطبيق شتريد للزبائن**. الكود داخل مجلد merchant_app، والحزمة Android الخاصة به عند توليد التطبيق: com.shitreed.shitreed_merchant.

## الإصدار الأولي 0.1.0 (قيد الاختبار)
- تسجيل الدخول وإنشاء حساب بالبريد مع Supabase Auth وإمكانية تأكيد البريد.
- تقديم طلب إضافة متجر باسم ومنطقة وتصنيف وعنوان وإحداثيات اختيارية. حالة المتجر تبدأ pending، ولا يظهر للزبائن حتى موافقة الإدارة.
- عرض قائمة المتاجر المملوكة للتاجر نفسه، وتعديل بياناتها وشعارها ووصفها وأوقات الدوام والعنوان والهاتف.
- إضافة منتجات حقيقية وأسعار بالدينار العراقي وكميات المخزون.
- اختيار صورة المنتج من معرض الهاتف ورفع JPEG/PNG/WebP بحجم حتى 5 MB إلى Supabase Storage، ضمن مجلد المتجر المملوك للتاجر.
- تحديث كميات المخزون، وتعديل المنتجات والأسعار والصور، وإخفاء المنتج وإعادة نشره دون حذف تاريخ الطلبات.
- مشاهدة الطلبات الخاصة بمتجر التاجر، وقبولها أو رفضها وتحويل المقبول للتحضير ثم جاهز للتسليم.
- لوحة إحصائية تعرض عدد المتاجر وحالات الطلبات وقيم الطلبات غير المحصلة، وليست أرباحاً أو مدفوعات مؤكدة.
- تسجيل خروج آمن.
- واجهة عربية RTL بنظام اللون البنفسجي والبرتقالي.

## البناء
المسار: .github/workflows/merchant-apk.yml من المستودع الأساسي، أو GitHub Actions > Shitreed Merchant Android APK.
ينشئ Flutter Android ويربط مشروع Supabase المستقل shitreed (ltwncrewggdrjevakwpb) باستخدام publishable key فقط. لا توجد مفاتيح service_role ضمن APK.
Artifact: Shitreed-Merchant-APK (ملف ZIP يحتوي app-debug.apk).
هذا **Debug APK للاختبار فقط** وليس نسخة إطلاق Play Store.

## حالة قاعدة البيانات
تطبيق الزبون وتطبيق التاجر **يستخدمان مشروع Supabase نفسه** مع سياسات RLS تحدد صلاحيات كل حساب. يجب عدم منح تاجر role admin أو تجاوز RLS. لا تنشئ بيانات بيع وهمية في إنتاج عام.

## قبل النشر التجاري
- لا توجد متاجر معتمدة ولا منتجات منشورة في حساب شتريد حتى آخر فحص.
- يجب اختبار تسجيل مستخدم وتاجر وتأكيد البريد والإدخال/الرفع/الطلب فعلياً من هاتف أندرويد بحسابين مختلفين.
- اعتماد المتاجر حالياً من إدارة قاعدة Supabase يدوياً، لا توجد لوحة Admin مستقلة مكتملة.
- عروض الخصم، صلاحيات فريق المتجر، إشعارات FCM الفعلية، إعداد التوصيل، التسليم والتحصيل، المالية والتسويات، التراسل والدعم، **لم تنفذ بعد**.
- تفعيل حماية كلمات المرور المسرّبة من Supabase Auth والمراجعة الأمنية للوظائف SECURITY DEFINER قبل استقبال زبائن.
- يجب إعداد توقيع RELEASE ثابت وإنشاء AAB وإفصاحات الخصوصية والاستيفاء الكامل لمتطلبات Google Play.
